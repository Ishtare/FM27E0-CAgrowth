# 当前构建的合同、俱乐部及退役适配

v1.1.20 已补充经完整版本、映像和原生代码核对的 Steam 27.1.0+2505117 适配，并保留旧构建及逐对象检查。新构建的只读连接已核对，实际应用与保存重载仍需分别验证，见 [27.1 适配](engine-27.1.md)。

适用已经通过原生签名核对的 Steam 27.0.1+2503222（game_plugin.dll 映像大小 0x185FA000）。其他渠道和构建不因版本号相似就使用这套布局。

## 修复原因

旧配置可能识别到球员，却没有正确识别当前构建的合同、财务和相关对象，导致依赖项目只读。退役入口此前只接受较早构建，日期识别还依赖挂牌球员样本。这些属于适配问题，不能通过关闭检查解决。

## 处理方式

- 完整版本、映像大小和原生签名一致后，使用核对过的对象类型。外部 profiles 仍优先，不覆盖使用者自定义配置。
- 财务编辑只接受完整财务对象；轻量财务对象不冒充完整结构。设施使用核对过的资料位置。
- 从带类型及重复读取检查的日期管理器取得游戏日期，供年龄、退役、挂牌及 CA 成长共用。
- 退役名单直接读取游戏当前存档的退役管理器，核对两份索引、身份、排序和计划记录。没有另外维护固定球员名单。
- 取消、推迟和残留状态修复保留事务、回读及撤销；应用前再次核对游戏日期。
- 人物性别与俱乐部性别交叉核对，通过后隐藏女足球员和女足俱乐部。

## 验证与限制

v1.1.14 的 12,700 项本地断言通过。生产代码只读检查通过合同、财务、设施、其他国籍、职员合同及日期项目；退役取消与推迟在读取副本中模拟通过，没有调用游戏写入。

v1.1.15 已继续补齐体能／士气、伤病、疲劳度、本队与租借号码、票价与季票，见 [五类功能说明](current-features.md)。当前构建仍保留逐对象检查，整体检查通过不保证每个对象都可编辑。实际修改效果、推进日期及保存重载需要分别核实。


v1.1.19 为这套已核实设施布局增加逐俱乐部、逐项目检查。少数设施异常不再关闭全部正常项目；0 值或未核实字段仍只读。其他构建不自动放开，见 [设施检查](facilities-validation.md)。
