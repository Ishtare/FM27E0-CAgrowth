## 更新后为何出现 0 家俱乐部与功能只读

收到的连接日志显示，旧版先按早期类型扫描，随后自动校准找回球员、职员等对象，但未找到完整财务类型，俱乐部列表因此为 0。体能、伤病等仍沿用旧配置，日期、退役及报名入口也没有取得本构建的已核实适配。

这次从安装的 game_plugin.dll 文件核对了类型信息、子对象偏移及相关机器指令，并以只读连接验证已载入存档。没有仅放宽版本白名单，也没有用统一的地址差值推导全部类型。

## 原生证明与字段

运行时要求四处独立代码片段匹配：非欧认定检查 0x16758CB、当前日期引用 0x23A2A5、退役根写入 0xC20AF5，以及体能字段写入 0x16445A3。日期入口从已验证代码取得，不依赖挂牌球员样本。读取日期和根指针后保留稳定性及有效值检查。

从原生代码另外核对了比赛状态、疲劳、士气、商业设施等字段的长度与位置。新适配保持体能／比赛状态两字节、士气单字节、疲劳有符号两字节；商业设施只接受完整财务对象。0 值、越界或归属不明的设施仍逐项只读，详见 [设施检查](facilities-validation.md)。

资格与报名共用当前构建的球队、国家、合同和赛事类型。只有完整识别且多份资料一致的规则可生成修改预览；带附加条件、不唯一或来源不一致的规则保持只读。意大利历史非欧认定的国家边界不变，未据版本升级扩展为所有联赛个人资格开关。
