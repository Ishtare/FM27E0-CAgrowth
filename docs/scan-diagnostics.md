# 扫描 0 人：反馈核查与诊断

v1.1.13，2026-11-15。

## 如何理解 0 人报告

只显示“已连接引擎、0 名球员”的截图不足以区分存档未就绪、读取失败和类型不匹配。需要结合本次连接详情中的实际统计判断，不能只凭版本号或联赛补丁名称下结论。

“未列入完整验证清单”属于版本提示，本身不会令球员数变为 0 或禁用编辑。具体功能由本次数据检查决定。

女足筛选及中文姓名补全在扫描之后执行。球员读取没有联赛名称白名单，俱乐部关联失败也不会因此丢弃已读取的球员。原始与保留人数可以帮助判断是否发生筛选。

## 仍然可能的条件

- 存档未完成加载、正在切换，真实对象尚不可读。
- 多个 fm.exe 或残留实例导致旧版静默连接到第一个进程。
- 同版本号的不同渠道／构建、旧外部 profiles 配置、自动识别被关闭，或布局确实不兼容。
- 内存区域查询或批量读取失败，或者候选的姓名、生日和属性检查未通过。

这些都是代码路径允许的条件；只有实际诊断可以进一步区分，不能把其他环境的口头描述当作本次已确认的原因。

## v1.1.13 的具体改动

1. 多个 fm.exe 时明确拒绝自动选取第一个；未找到 game_plugin.dll 时明确提示引擎尚未就绪，停止把启动程序当作引擎扫描。
2. 挂接报告显示修改器版本；核心检查失败时显示连接环境、读取统计、类型命中、筛选前后人数和最多两组校准候选摘要。完整候选结果保留在“连接详情…”及变更记录。
3. 记录批量读取错误码与区域查询停止信息；本机 API 声明使用 SetLastError=true 保存错误。地址超出进程可访问范围也会结束查询，不能把任何查询停止都解释为故障。批量扫描失败计数不是所有独立字段读取失败的总数。
4. 校准按原有规则记录前五组属性候选的数量，以及姓名／生日抽样通过数。数量不足时注明未执行身份抽样，不伪造为零通过。
5. 明确版本清单提示本身不阻止扫描或编辑。连接失败写入本次报告；开始重扫时停止冻结及 CA 成长，避免连接失败后继续沿用旧任务。

未放宽球员数量、类型、属性、姓名、生日或逐功能检查，未修改联赛过滤条件，未关闭只读保护。没有宣称自动修复了本次网友的 0 人故障。本版不改变批量读取分块、候选排序、抽样范围或字段布局。

## 本地验证与限制

12,678 项本地断言通过，涵盖原有功能及新增的目标进程歧义、错误码保留声明、诊断计数、候选淘汰原因、外部配置说明、报告长度限制、全名单检查与版本提示分离。源码包离线重新构建与检查另见 VALIDATION.md。

诊断功能通过离线检查，尚未复现仅有截图的论坛故障，不能宣称解决所有 0 人扫描情况。

以后如再次遇到此问题，可保留完整挂接报告截图，或从底部“连接详情…”选择“复制本次诊断”。不需要提供私人存档。先看诊断事实，再决定是否需要具体渠道的布局适配。
